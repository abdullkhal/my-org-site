# Founder operations

## Run the PIIK weekly intelligence cycle

Read the latest collection artifact and operating policies. Deduplicate leads and inspect original sources where permitted. Review facts and prepare eligible articles, notices and the Kenya Property Brief. Keep uncertain items private. Validate and publish eligible items through [the release process](#release-process). Generate one executive report with [automation instructions](AUTOMATION.md).

## Run the PIIK directory expansion cycle

Choose underserved categories or regions. Review original public organisational sources and applicable authorities. Record services, public contact channel where appropriate, scope, last review and limitations. Search for duplicates. Add only eligible profiles through the normal release process. Review stale entries each month.

## Conduct a PIIK website health audit

Run the README checks and inspect the latest Actions collection and integrity runs. Check release parity on the public domain and inspect monitored sources for failures and stale evidence. Record intentional skips, permissions and network constraints. Consolidate open exceptions in the executive report.

## Continue the next approved roadmap priority

Open [the roadmap](../ROADMAP.md) and [the changelog](CHANGELOG.md). Resume the first incomplete phase at its checkpoint and verify its gate before enabling dependent features.

## Release process

Regenerate outputs, review the diff, run checks and use the authorised GitHub branch and pull request workflow. Merge after required checks pass. Inspect Pages and the production smoke job for the exact release SHA. For rollback, revert the release through the same workflow and verify the restored public files. Preserve the prior working release when validation fails.
